# Спецификация продукта — TaskFlow

**Статус:** утверждена для учебной реализации. **Версия:** 1.0.

## 1. Проблема и цель

Пользователю нужен простой личный список дел, который помогает увидеть объём работы, быстро найти задачу и отметить продвижение. Учебная цель — провести работу по SDD и продемонстрировать приложение Django, PostgreSQL и Valkey в Docker Compose, а также связку OpenCode + MCP + Skill + AGENTS.md.

## 2. Пользователь и границы

Целевой пользователь — один человек, ведущий личный список задач. Аутентификация, совместная работа, уведомления, проекты, вложения и публичный production-деплой не входят в первую версию. Django admin оставлен как демонстрационный интерфейс управления.

## 3. Основные сценарии

1. Пользователь открывает главную страницу и видит статистику: всего, активных и завершённых задач.
2. Создаёт задачу с названием и при необходимости описанием, статусом, приоритетом и сроком.
3. Ищет задачи по названию/описанию и фильтрует по статусу.
4. Открывает карточку, редактирует или удаляет задачу.
5. Переводит задачу по циклу «К выполнению → В работе → Готово → К выполнению».

## 4. Функциональные требования

- **FR-1:** задача имеет обязательное название (до 160 символов), необязательное описание и срок, один из трёх статусов и один из трёх приоритетов.
- **FR-2:** приложение поддерживает CRUD задачи; изменяющие действия выполняются POST-запросами с CSRF-защитой.
- **FR-3:** список поддерживает поиск без учёта регистра по названию и описанию, а также фильтр по статусу.
- **FR-4:** главная показывает общее, активное и завершённое число задач.
- **FR-5:** статистика кэшируется на 60 секунд в Valkey и инвалидируется при создании, изменении или удалении задачи.
- **FR-6:** приложение имеет русскоязычный интерфейс, адаптивную вёрстку и пустое состояние списка.
- **FR-7:** схема БД управляется миграциями Django; администратор может смотреть/искать/фильтровать задачи через admin.

## 5. Нефункциональные требования

- **NFR-1:** приложение запускается в Docker Compose с отдельными сервисами web, PostgreSQL и Valkey; web ждёт healthcheck двух зависимостей.
- **NFR-2:** секреты и параметры локального запуска задаются переменными окружения; секреты не коммитятся.
- **NFR-3:** локальная разработка и автоматические тесты могут использовать SQLite и локальный кэш, если DB_HOST/VALKEY_URL не заданы.
- **NFR-4:** документация OpenCode содержит проектные правила, переиспользуемый SDD Skill и read-only MCP server, ограниченный чтением артефактов этого репозитория.
- **NFR-5:** критические пользовательские сценарии покрыты Django-тестами.

## 6. Критерии приёмки

- **AC-1:** чистый проект запускается командами из README; миграции выполняются автоматически в Compose.
- **AC-2:** главная возвращает HTTP 200 и показывает корректные счётчики.
- **AC-3:** задача создаётся, отображается, обновляется, меняет статус и удаляется.
- **AC-4:** поиск и фильтр ограничивают выдачу ожидаемо.
- **AC-5:** изменение задачи очищает кэш статистики.
- **AC-6:** `python manage.py check` и `python manage.py test` проходят.
- **AC-7:** Compose-конфигурация определяет web + PostgreSQL + Valkey, healthchecks, конфигурацию через env и постоянные volumes.
- **AC-8:** OpenCode обнаруживает `sdd-workflow`; MCP-сервер публикует инструменты чтения статуса SDD и списка документов.

## 7. Метрики демонстрации

Показать работающие три сервиса (`docker compose ps`), создать задачу в браузере, найти/отфильтровать её, пройти статусы, показать обновление статистики и запустить тесты. Отдельно показать `/mcps` и загрузку Skill в OpenCode.
