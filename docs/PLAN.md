# План реализации — ExamPrep

## Архитектура

- Django-проект `taskmanager/`; приложение `tasks/` отвечает за карточки экзаменационных вопросов.
- Модель карточки содержит предмет, тему, вопрос/ответ, сложность и состояние повторения.
- Серверные шаблоны отображают список, форму, подробную карточку и режим тренировки.
- Статистика главной кэшируется Valkey; сигналы сбрасывают ключ после мутаций.
- Compose: web + PostgreSQL 16 + Valkey 8, с healthchecks и volume для данных.
- `.opencode/` содержит локальный MCP и переиспользуемый SDD Skill; `AGENTS.md` задаёт процесс.

## Этапы SDD

1. **Discover:** определить персону, сценарии подготовки и границы продукта — `SPEC.md`.
2. **Design:** согласовать поля карточки, состояния повторения, выдачу due-вопросов, кэш-ключ и Compose — `DECISIONS.md`.
3. **Plan:** декомпозировать реализацию и проверку критериев в `TASKS.md`.
4. **Implement:** миграция Task → StudyCard; CRUD и каталог; поиск/фильтры; режим тренировки; Valkey-инвалидация; тесты.
5. **Verify:** Django checks/tests, миграции, проверка MCP, Compose и ручная демонстрация.

## Риски и меры

- Отсутствие Docker: SQLite/local cache позволяют разрабатывать и тестировать отдельно; PostgreSQL/Valkey Compose остаётся целевым исполнением.
- Данные старого TaskFlow: миграция переименовывает модель/поля и сохраняет прежние записи, добавляя предмет «Общий предмет».
- Повтор одной карточки: после «Повторить завтра» карточка получает следующую дату и не попадает в очередь сегодня.
- MCP-инструменты остаются read-only и читают только фиксированный список SDD-документов.

## Definition of Done

Все критерии AC-1…AC-8 реализованы и проверены; ограничения вроде недоступного Docker/OpenCode отмечены отдельно, а не заявлены как пройденные.
