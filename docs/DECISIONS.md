# Архитектурные решения

## ADR-001 — предметная область

**Решение:** личный трекер задач TaskFlow.

**Причина:** компактная и наглядная предметная область позволяет показать полный цикл CRUD, фильтрацию, бизнес-статусы, метрики и кэш без ненужной сложности.

## ADR-002 — SDD как обязательный процесс

**Решение:** спецификация, план и чек-лист являются исходными артефактами; правила закреплены в `AGENTS.md` и Skill `sdd-workflow`.

**Причина:** задание оценивает SDD и демонстрацию агентских инструкций, поэтому процесс должен быть видимым и воспроизводимым.

## ADR-003 — Django + PostgreSQL + Valkey

**Решение:** Django 5.2 для веб-слоя, PostgreSQL 16 для контейнерной БД, Valkey 8 как Redis-совместимое хранилище кэша. В локальном режиме без инфраструктуры — SQLite и LocMemCache.

**Причина:** соответствует заданию, но сохраняет быстрый цикл локальных тестов.

## ADR-004 — кэшировать только агрегаты дашборда

**Решение:** кэшировать счётчики под версионным ключом `taskflow:dashboard:v1` на 60 секунд, инвалидировать через Django signals после save/delete.

**Причина:** простой сценарий позволяет показать пользу Valkey и проверяемую инвалидацию, не усложняя CRUD.

## ADR-005 — MCP только для чтения

**Решение:** локальный stdio MCP-сервер публикует только чтение статуса SDD и перечня документов.

**Причина:** агенту полезны контекст и прогресс, но запись через MCP не нужна; ограниченный набор безопаснее и легче демонстрируется.
