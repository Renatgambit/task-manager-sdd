# Архитектурные решения — ExamPrep

## ADR-001 — предметная область

**Решение:** веб-приложение подготовки к экзамену. Основная единица — карточка с вопросом и ответом, привязанная к предмету и теме.

**Причина:** это исходная область задания на слайде; TaskFlow был альтернативой и не отражал требуемое назначение.

## ADR-002 — SDD

**Решение:** сначала спецификация, затем план/задачи и реализация; правила закреплены в `AGENTS.md` и Skill `sdd-workflow`.

## ADR-003 — очередь интервального повторения

**Решение:** карточка имеет состояние `new`, `review` или `known`. «Знаю» переводит в known; «Повторить завтра» назначает `next_review` на следующий день. В сессию входят только новые и due-карточки.

**Причина:** сценарий понятен для экзаменационной демонстрации и проверяется без внешних сервисов.

## ADR-004 — инфраструктура варианта №5

**Решение:** Django 5.2, PostgreSQL 16, Valkey 8 в Docker Compose; локальная разработка использует SQLite/LocMemCache.

## ADR-005 — MCP с чтением SDD

**Решение:** MCP сервер публикует только чтение статуса и фиксированных SDD-артефактов.

**Причина:** агент получает контекст процесса, не расширяя доступ до записи в проект.
